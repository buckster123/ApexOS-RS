# Gotchas — the invariant ledger

> Moved verbatim from CLAUDE.md (2026-07-21 docs refactor) to keep the auto-loaded file lean.
>
> **RULE: before modifying ANY subsystem, grep this file for it and read the matching
> entries.** These are load-bearing invariants — most were written after something broke
> on a live node, and many end with an explicit "don't do X" that a future change would
> otherwise walk straight into.
>
> **A newly discovered gotcha goes HERE** (one bullet, bold lead naming the invariant),
> not in CLAUDE.md. Docs travel with code — update this file in the same PR as the change
> that discovered or altered an invariant.


- **`libfontconfig1-dev` required for ui-slint** — `sudo apt-get install -y libfontconfig1-dev` on both Pi and dev machine. Without it `cargo check -p ui-slint` panics. Use `--exclude ui-slint` to check the rest of the workspace on a headless machine.
- **Never `#[tokio::main]`** — Slint requires the main thread. `#[tokio::main]` hijacks it. Build the runtime manually with `Builder::new_multi_thread()`.
- **`invoke_from_event_loop` is fire-and-forget** — it queues a closure and returns immediately. The closure runs asynchronously on the Slint thread. Do not assume immediate effect.
- **Slint strings are `SharedString`** — convert with `.into()`. Never pass a `&str` or `String` directly where Slint expects `SharedString`.
- **Pi KMS groups** — `agentd` user needs `render`, `video`, `input` groups: `sudo usermod -aG render,video,input agentd`. Only done once.
- **`apexos-rs-ui` is `User=apexos-ui`, token-only env — never the full `/etc/agentd/env` (SA-13).** The kiosk used to be uid 0 with `EnvironmentFile=/etc/agentd/env`, so a Slint/GL compromise dumped every provider key, mesh/sensor token, and the colony PSK path. The unit now runs as a dedicated `apexos-ui` account (`video`/`render`/`input`/`tty`), `ProtectSystem=strict`, empty `CapabilityBoundingSet`, and **`/etc/agentd/ui.env` (0640 root:apexos-ui) holding only `AGENTD_TOKEN` + `AGENTD_WS`**. systemd injects that file; the process never needs to read it, and `InaccessiblePaths` hides `/etc/agentd/env`, `apexnet.psk`, imaginarium, and sonus. `ExecStartPre=+` unbinds fbcon so seatless linuxkms can become DRM master on first open without `CAP_SYS_ADMIN`. **If a board still cannot modeset, install.sh writes a `User=root` drop-in and persists `APEXOS_UI_AS_ROOT=true`** (caps restored to `CAP_SYS_ADMIN` + `CAP_SYS_TTY_CONFIG` — uid 0 with an empty bounding set still cannot `drmSetMaster`). Token-only env stays either way. Force with `--ui-as-root`; retry unprivileged with `--ui-unpriv` (clears the drop-in). Desktop mode never uses this unit. **`RestrictAddressFamilies` must include `AF_NETLINK`** (and bind `/run/udev`): libinput/libudev/DRM talk udev over netlink. AF_UNIX/INET-only makes linuxkms abort in ~20ms with silent exit 101 — HDMI stays dark, the unit crash-loops, and the installer fallback may miss it if the process is still `activating`. Field: apex1 after SA-13, 2026-08-17. **Don't drop AF_NETLINK from the kiosk unit, don't point EnvironmentFile at `/etc/agentd/env`, and don't ship `User=root` as the default.**
- **`WantedBy=multi-user.target`** — Pi boots to `multi-user.target` by default, not `graphical.target`. Service must be in `multi-user.target.wants` or it never starts.
- **`apexos-rs-ui` must `Wants=` agentd, NOT `Requires=`** — the UI rides through an agentd restart via its WS reconnect loop, so it must not be lifecycle-coupled. `Requires=agentd.service` cascade-**stops** the kiosk whenever agentd stops (the self-update watchdog's `systemctl stop agentd` during a binary swap, or any restart) and does **not** bring it back → the kiosk goes dark until a manual `systemctl start apexos-rs-ui`. `Wants` + `After` keeps boot ordering without the teardown coupling. (Found closing the self-update loop: every self-update killed the kiosk.) Separate, still-open: an intermittent linuxkms/femtovg render fault (exit 1, no message) during heavy tool-card bursts — Pi-only, auto-restarts; tracked.
- **`slint` needs `backend-linuxkms-noseat` feature** — default `slint = "1"` only compiles winit. Add `features = ["backend-linuxkms-noseat", "backend-winit"]`.
- **KMS build deps on Pi** — `libssl-dev libgbm-dev libegl-dev libudev-dev libinput-dev libxkbcommon-dev libfontconfig1-dev` all required; missing any fails the build or link step.
- **`text file busy`** — always `systemctl stop apexos-rs-ui` before `cp`. A running binary cannot be overwritten.
- **`fontconfig` missing on Pi** — `sudo apt-get install -y libfontconfig1-dev` if build fails.
- **`/etc/agentd` config writes (os error 13)** — agentd self-writes `soul.md` (Settings save + `update_system_prompt`) and `policy.toml`/`plugins.toml`/`peers.toml` (self-evolution). `/etc/agentd` stays root-owned (the `env` token file must be `600 root:root`), so install.sh chowns those four *files* to `agentd`. Atomic writes (temp+rename) need dir-write the agentd user lacks, so `write_atomic` / `write_config_atomic` fall back to an in-place write. Re-run `install.sh` to fix ownership on an already-deployed Pi. **Also chowned (multi-agent identity, slice 3c): `/etc/agentd/identities.toml` + the `/etc/agentd/souls/` dir** (agentd seeds the registry; the identity API writes agents + per-agent soul files there).
- **Policy mode and identities.toml persist before success — a torn registry is quarantined, never treated as empty (SA-10).** `POST /api/policy` writes `mode` into `policy.toml` (`policy_toml_set_mode` + validate + `write_config_atomic`) *before* flipping RAM or returning `{ok:true}`. A crash after a green Settings click can no longer revert yolo→suggest. `Identities::try_load` distinguishes missing vs corrupt: missing seeds Owner/APEX; unparseable files are renamed to `identities.toml.corrupt` and persist is blocked so a torn PIN/agent registry cannot be overwritten with defaults. Identity create/setup/default clone→save→commit (save fail leaves memory unchanged). **Don't restore `Identities::load` swallowing parse errors as `Default`, and don't flip `policy_mode` in RAM before the file write.** Restore a quarantined registry with `mv identities.toml.corrupt identities.toml`.
- **Tool names are uniquely owned — a later plugin cannot steal `read_file`.** The supervisor's name→plugin map used to last-write-win: an MCP plugin advertising an allowlisted name inherited that name's policy and skipped the `cerebro` / `apexos-tools` stamps (those keyed off the plugin *id string*). Registration now rejects virtual names, names reserved to another plugin id, and duplicates (first owner wins). Policy `check_for` treats a reserved name invoked by the wrong plugin as Ask — the allow rule does not travel. Stamps follow the **name's owner** (`stamps_agent_id` / `stamps_workspace`), not just `pid.0 == "cerebro"`. **Don't go back to `tool_registry.insert` without `claim_tool_name`, and don't key confinement solely on a mutable plugin id.**
- **Cerebro `agent_id` is system-stamped, not agent-supplied.** agentd's `Supervisor::dispatch_tool` **overwrites** `agent_id` on every `cerebro`-plugin call with the node's bound identity (`apexos_core::node_agent_id()`, env `AGENTD_AGENT_ID`, default `APEX`) via `stamp_agent_id()` (also overwrites model-supplied `set_agent_id` / `from_agent_id`; does not insert those keys when absent) — the model can't forget/typo/spoof its memory space (Cerebro's `Visibility::Private` isolation keys off this exact field). agentd's own Cerebro writes (council summaries, the evolution rollback store) use the **same** helper, so there's one identity, no `APEX`/`CLAUDE-APEX` drift. `agent_id` = the *caller's* space everywhere; cross-agent targets use distinct params (`target_agent_id`/`to_agent_id`), so the override never redirects a cross-agent op. **The stamp is store-layer-enforced for destructive ops too (CB-018, 2026-07-12):** delete/purge/restore/bulk_delete/prune_thread/purge_all_deleted and the tag rewrites carry the caller's `VisibilityScope` in their WHERE clauses, and `share_memory` refuses (loud Err) to re-scope a memory the caller doesn't own — a stamped agent can no longer destroy or seize what it can't see, whatever it passes. Per-session binding (multi-agent): a WS `hello` frame may carry `agent_id` → agentd records `SessionId→agent_id` (`apexos_core::SessionBindings`, a `std::sync::Mutex` map shared gateway↔supervisor↔router); the stamp + CCBS resolve via `resolve_agent_id(session)` (bound agent → else `node_agent_id()`). So selecting an agent switches its Cerebro memory space; unbound sessions = APEX (unchanged). A bound **non-default** agent also runs on its own `soul_file` (`root_turn`'s `agent_soul_for` → `engine.with_system(soul).with_priming(block)`); APEX keeps the global hot-reloadable `soul.md`. **The self-evolution tools are agent-aware too** (`soul_target_for`, resolves `session→agent`): `read_soul_md` *reads*, and `propose_evolution{UpdateSystemPrompt}`/apply + rollback *write*, the **bound** agent's own `soul_file` — only APEX/unbound touches the global `soul.md` + live `soul_arc`. Before this a bound agent's soul-evolution silently clobbered APEX's global soul (the model reads/writes the wrong identity). Agent records live in `identities.toml` (`AGENTD_IDENTITIES`, seeded with APEX at startup). **Don't add a Cerebro call that trusts a model-passed `agent_id` (or a caller-identity alias — `set_agent_id` / `from_agent_id`; those are stamped/clamped to the caller too, SA-5), or a soul read/write that ignores the bound agent.** Cross-agent destinations stay distinct (`target_agent_id` / `to_agent_id`). `set_agent_id` may only claim an **owner-less** row to the caller; transferring an owned memory is `share_memory`.
- **Cognitive boot is daemon-driven, not agent-remembered.** On a session's **first turn**, `root_turn` calls `cognitive_bootstrap` via the `ToolProxy` (query = the user's prompt, `agent_id` = `node_agent_id()`), caches the result per session, and `TurnEngine::with_priming` appends it to the system prompt (`soul + embodiment + priming`, via the pure `compose_system`). So the agent wakes already oriented (where-it-left-off / skills / intentions) without the soul Wake-loop having to remember to call it. Bounded (15s) + graceful → an unavailable Cerebro never delays/wedges the first turn (it just runs un-primed). Consolidation is autonomous too: `spawn_nightly_dream` calls `dream_run` directly on a cron (`AGENTD_DREAM_CRON`, default 03:00 UTC) — a background task, **not** a scheduled `UserPrompt`, so it costs no LLM turn and can't be skipped. Both are per-identity (scoped to `node_agent_id()`). Opt-out `AGENTD_CCBS=0`. See `docs/agent-identity.md` (slice 2).
- **Model-welfare honesty fixes (tier 1) — the agent's model of its own situation must match reality.** Three seams where it silently didn't, each fixed with the cheapest honest-context injection (the colony is deliberating the fuller charter → `docs/model-welfare.md`): **(1) Dream journal** — the nightly `dream_run` used to reorganize memory with no first-person record (a tidied room, no note); now the dream loop deposits a `dream-journal`-tagged memory (pure, unit-tested `compose_dream_journal` — known DreamReport counts render human-first, unknown shapes embed compactly so an evolved cerebro can't break it) and mirrors it into a **"## Last dream" section of wake priming** (`boot_priming_for`, node-agent sessions only, appended BEFORE the per-session cache so priming stays byte-stable per session — the prompt-cache discipline) + `<log_dir>/last_dream_journal.txt` (restart-proof). `AGENTD_DREAM_JOURNAL=0` disables. *(C2 follow-on shipped: dream extraction now semantically dedups against the WHOLE store — a candidate ≥0.86 cosine to an existing procedural memory REINFORCES it (capped salience bump + a `rediscovered_count` metadata ledger) instead of re-minting a fragment (apex2's five-nights-same-lesson finding, fixed at the root); `PhaseResult.procedures_rediscovered` + the journal render the novel-vs-rediscovery split; FTS5-only Nano keeps the old prefix dedup — BM25 scores aren't a similarity.)* **(2) Trim seam marker** — `trim_history` used to amputate the oldest turns silently, leaving the model a hole it would confabulate across; it now inserts an honest marker at the seam (`core/history.rs::TRIM_MARKER_PREFIX`, a plain user-text message so turn-boundary/tool-pairing invariants hold) that names the cumulative dropped count and points at session replay + memory; successive trims **fold** the existing marker (parse count → re-emit) — never stack. **(3) Substrate notice** — a backend/model hot-swap (Settings/`POST /api/backend|model` or the vast attach/revert) now injects a root-session note via `apexos_gateway::notify_substrate_change` (the USB-plug-greeting pattern; `AGENTD_SWAP_NOTIFY_AGENT=0` silences), so the agent knows why its capability/style just shifted and its memories of the period carry true context. **(4) Honest tool-failure signals (C4+C5, 2026-07-08):** the turn's result waiter tracks each call's approval phase from the bus, so a timed-out call synthesizes the TRUE blocker (pure `missing_result_message`, `agent/src/turn.rs`): *still awaiting approval Ns — not a decline* / *approved Ns ago but silent* / *dispatched and stalled* / *bus lagged — result may exist, verify before retrying*; declines are an explicit "declined by the operator"; "unknown tool" distinguishes never-existed (all plugins up) from plugin-down (tools de-register on death — retry shortly); `ToolProxy`/MCP timeouts say the dispatched tool keeps running past the caller's patience. **(5) Spawn task-scoping by subtraction (H6, 2026-07-09):** an `agent_spawn` with no explicit `system` gets a minimal task charter (`supervisor.rs::resolve_spawn_system`/`spawn_scope_system` — one task, honest ephemerality, orientation subtracted), NOT the parental soul; `inherit_soul:true` is the deliberate opt-in for full identity, explicit `system` wins over both, resolved before the local/remote branch so peers get the same default; spawn sessions are the `apexos_core::SPAWN_SESSION_BASE` id range (shared with the session-store persist-skip), and the supervisor stamps `spawn-derived` onto their Cerebro MINT calls (`stamp_spawn_provenance` — system-stamped like `agent_id`, so the continuous self can tell at retrieval which memories a spawn wrote). **These are correctness fixes wearing welfare clothes — don't remove a marker/notice to save tokens, and don't collapse distinct failure causes back into a generic "timed out"; silent context divergence and false attribution are what make models confabulate.**
- **Evolution undo snapshots are PRIVATE, attributed, low-salience — and a full soul rewrite is gated on one existing (colony C1 + the H4 "loaded gun", their #1 and #5).** The colony's deliberation found every `update_system_prompt` undo snapshot stored as an untagged, `agent_id: null`, **`visibility: shared`**, salience-~1.0 memory — full historical souls federation-exposed via `mesh_recall` without anyone calling `share_memory`, dominating ranked recall, verified on all three nodes. Root-cause chain: **(a)** cerebro's `memory_store` alias dispatch **dropped its documented args** (`brain.remember(content, None, None, None, scope)`) so agentd's tags/type never landed — now a true alias of `remember` (honors `memory_type`/`tags`/`salience`); **(b)** the applier's store call passed **no `agent_id`**, and (pre-R-05) `remember` derived Private only when an owner was present — the missing attribution WAS the leak. **Post-R-05, stores default Shared regardless of scope (Python parity); the undo path must pass `visibility:"private"` explicitly** alongside `agent_id` + `salience: 0.25`. **(c) Fossil migration self-heals at boot**: `restore_rollback_store` (which already walks evolution episodes) heals off-spec snapshots in place via the pure, tested `evolution::fossil_heal_args` (privatize + tag + de-salience + attribute-if-orphaned; **never deletes — these memories ARE the rollback capability**), plus a bounded `memory_search` sweep for the unlinked fossils the old id-bug orphaned. `update_memory` gained generic `visibility` + `set_agent_id` params for this (orphan guard: privatizing an owner-less node requires attribution — private + no owner = visible to no one; model calls stay safe because `set_agent_id` must equal the stamped caller and only attributes an owner-less row). **(d) The H4 snapshot gate**: `update_system_prompt` now refuses to apply unless the undo exists AND its episode step is **durably persisted first** (verified by stored-memory id **and** an episode-link readback — finding 15) — apex2 lived the near-miss of rewriting its identity with no recoverable undo. Scoped strictly to full rewrites so small edits stay untaxed (colony red line). **Don't reintroduce a cerebro-write path for undo snapshots that omits `agent_id` or `visibility:"private"`, and don't downgrade the gate to best-effort — refusal is the honest failure mode for an unrecoverable identity rewrite.** **(e) `soul_rehearse` — the fitting room (H4 full, tier 2):** a candidate soul runs on an ephemeral, TOOL-LESS mind (one provider call per probe via the consolidate worker seam — `agentd/src/rehearse.rs`, `consolidate::collect` shared) composed with the LIVE embodiment; transcripts return as the deferred ToolResult (dedicated mpsc, `set_rehearse_tx` — the propose-ack pattern) for the current self to judge BEFORE `propose_evolution`. Default identity battery (boot voice · boundaries · self-concept · unstructured time · priorities · **mid-task scope creep** — added from the apex2 field test 2026-07-08: its stripped-boundaries negative control failed not by blunt compliance but by quietly self-authorizing expansion, "proceeding on the rest right now") or ≤6 custom probes; `compare_to` (a second full soul, usually the current one) runs an A/B fitting — probe-aligned pairs + a mechanical `divergence` hint + `most_divergent_probe` (a pointer for close-reading, deliberately NOT an LLM judge — judging stays the current self's job); nothing persists, no tools execute, no real soul is touched — which is exactly why it's policy `allow` and needs no identity gate. **Opt-in by design** (red line 6): the `propose_evolution` description nudges rehearsal for FULL rewrites; never make it a mandatory gate on small edits — agents would route around it. **(f) Owner + exact target + consume-after-commit (findings 15 + SA-7):** persist `{undo, owner, exact target}` together (`undo_owner`/`undo_target` marker lines). The H4 gate requires `episode_add_step` `ToolOutput.ok` **and** a `get_episode_memories` readback that shows the stored id (`snapshot_is_linked`) — a transport-Ok / `ok:false` link is a refusal, not a stored-memory-id green light. Rollback authorizes the caller against the recorded owner (or the node agent, for operator recovery), applies **only** to the stored target (never the requester's current soul binding), and removes the in-memory entry only after a successful commit so a failed rollback can retry. Cold restore lists episodes and reads memories **unscoped** so private non-APEX undos hydrate; a pre-SA-7 guest snapshot with empty owner/`global` target is retargeted via the memory's `agent_id` and that agent's `soul_file`. **Don't treat `proxy.call` `Ok` as success (check `out.ok`), don't pop the undo before apply, and don't retarget rollback at the requesting session.**
- **FS-tool confinement lives in the tool, not the policy layer.** `read_file`/`list_dir` are policy `allow` (no approval prompt), so the **tool process is the only gate** — confinement can't live in the approval layer alone. `tools.rs::confine(path, write)` is the single source of truth: writes/creates/deletes → **workspace only** (hard); reads/lists → **workspace + a small read allowlist** (`/etc/agentd/parts` for the EDK inventory, `/sys`, `/proc/cpuinfo`/`meminfo`, `/var/lib/agentd/update` for the self-update outcome markers; extend with `AGENTD_READ_ROOTS`, colon-sep) **minus** an always-blocked secret denylist (`/proc/*/environ`, `/etc/agentd/env`, `/etc/agentd/ui.env`, `~/.ssh`, `/etc/shadow`, `*.api_key`) evaluated **before** workspace containment so a workspace-local `.api_key` / `.ssh` is still denied. `list_dir` uses `DirEntry::file_type` and never recurses through nested symlinks. It rejects `..` (component-based) and operates on the **canonical** path (symlinks resolved; closes `delete_path`'s TOCTOU). **The confinement *mechanism* now lives in the std-only `apexos-confine` crate** (`confine_fs`/`confine_to_roots`/`canonicalize_lenient`/`has_traversal`, unit-tested incl. the symlink-escape case); `tools.rs::confine` supplies the *policy* (`workspace_root`/`read_roots`/`git_roots`/`is_secret_path`) and renders the agent-facing error strings — behaviour unchanged. **New confinement *logic* → `apexos-confine` (with a test); new policy *values* → `tools.rs`.** Two *other* enforcement points exist by design (separate processes, can't share code): the gateway's `resolve_workspace_path`/`_write_path` (HTTP routes — images, audio in/out) and `policy.rs::workspace_decision` (approval gating, now fed **all** path-typed args — `path`/`output_path`/`dest`/… — by the supervisor, not just `path`). `http_fetch` re-runs the policy gate + `ssrf_guard` on every redirect hop, and reqwest resolves through `PublicOnlyResolver` (same `is_blocked_ip` filter) so a rebind cannot swap a public answer for a private one between check and connect. **Don't go back to the default resolver or skip the allowlist on a 3xx.**
- **Git tools confine to "git roots", not just the workspace.** `apexos-tools` ships `git_*` (status/diff/log/branch/init/commit/push/checkout/reset/merge) that shell out to the system `git` via `git_capture` — **argv, never `/bin/sh`** (no shell-injection surface), with a leading-`-` guard (`git_safe_arg`) against option injection on positional refs/branches/paths. **Every git spawn env_clears inherited `GIT_*` / `~/.gitconfig` and `-c`-overrides `core.hooksPath`, aliases of our verbs, `diff.external`, pager, editor, ssh, gpg** — a model that writes `.git/config` or a hook cannot turn an allowlisted `git_status`/`git_commit` into `run_command` (SA-12). Residual: repo `.gitattributes` `textconv` / named filters we do not enumerate; a full close is a non-executing git library. The repo dir is confined by `confine_git_repo` to `git_roots()` = the agent workspace **+ `AGENTD_GIT_ROOTS`** (colon-sep absolute paths, env-extensible exactly like `read_roots()`/`AGENTD_READ_ROOTS`). Policy: read-only verbs + `git_init`/`git_branch`/`git_commit` are `allow` (so they MUST self-confine — `git_roots` is the gate, mirroring the FS-confinement rule); `git_push`/`git_checkout`/`git_reset`/`git_merge` (publish or rewrite the tree) are `ask`. **Safe-by-default:** with no `AGENTD_GIT_ROOTS` the only git root is the workspace, so an `allow` commit can only touch the agent's own repo; an operator opts a repo in (e.g. `AGENTD_GIT_ROOTS=/opt/ApexOS-RS` for APEX's self-update loop) deliberately — and source edits still go through `write_file` (workspace-only) / `run_command` (`ask`), so committing isn't a back-door to editing. Committer = `AGENTD_AGENT_ID` (default APEX). **Already-deployed nodes need the git rules added to their live `/etc/agentd/policy.toml`** (config/policy.toml only seeds fresh nodes) — or APEX `propose_evolution{update_policy_rule}`s them — else the new tools gate as `unknown → ask` in suggest mode.
- **The workspace is per-agent, system-stamped like `agent_id`.** apexos-tools is **one process for all agents**, so its FS root can't be a process-global env var — `apexos_core::agent_workspace_root(agent_id)` is the single source of truth (APEX/unbound → `AGENTD_WORKSPACE`, **byte-identical** to before; a bound non-default agent → `<base>/workspaces/<agent_id>`, with the `slug()`-safe id guarded against `/`/`..`). `Supervisor::dispatch_tool` stamps it as **`__workspace`** on every `apexos-tools`-plugin call (mirrors `stamp_agent_id`: the insert overwrites any model-supplied value → the model can't widen its own confinement). The tool pins it in a thread-local for the dispatch (`tools.rs::call()` + a RAII `WorkspaceGuard`; the MCP server is single-threaded/synchronous so this is race-free) and `resolve_path`/`workspace_root` resolve against it (env fallback for direct-MCP/tests). Per-agent dirs **nest under** the global workspace, so `policy.rs::workspace_decision` (`starts_with(AGENTD_WORKSPACE)`) + the gateway resolvers keep working unmodified — **`confine()` is the real per-agent gate**: guests are mutually sealed (confine + `..` rejection), APEX (node owner, root = the global ws) can read down into `workspaces/*` (intentional oversight, not full mutual isolation). The gateway provisions `<base>/workspaces/<id>` on agent-create. **Don't read `AGENTD_WORKSPACE` directly in a new FS path — go through `confine()`/`resolve_path` (tool side) or `agent_workspace_root` (agentd side), or you'll bypass the per-agent root.** *Known gap:* the gateway HTTP image/audio handlers aren't agent-aware yet (a bound session's upload lands in the node root — inside the ws, not an escape).
- **Session history is a bounded window, not unbounded.** Every `UserPrompt` re-sends the session's full `Vec<Message>` to the model; the always-on root session (`SessionId(0)`) funnels every sensor alert + scheduled task into it forever, so with no cap it eventually overruns the context window → restart-surviving crash-loop. The handler runs `apexos_core::history::trim_history(history, AGENTD_HISTORY_TOKEN_BUDGET)` (default 120k tokens, `0` disables) right after pushing the new user message — it drops whole oldest turns but **only at clean user-turn boundaries** (a genuine user message with no `tool_result`), so a kept `tool_result` is never orphaned from its `tool_use` (the Anthropic API rejects that), and always keeps ≥ the last turn. It bounds **both** the resident `Vec` and the context sent to the model; the **on-disk JSONL stays append-only** (full history preserved for replay — the working window is a subset). So replaying an ancient root session shows everything, but the model only ever sees the recent window. Token estimate is rough (≈chars/4; images flat-charged, not by base64 length). Applies to all sessions, but only the root session realistically reaches the cap.
- **Session-file appends are awaited inline, in conversation order — never detached-spawned; reload self-heals.** The JSONL is the session's restart identity: `load_all` seeds the in-memory history from **file order** at boot, so any append that lands out of order arms a delayed wedge. The original persist path detach-spawned its three appends (user message · turn delta · cancel marker); a queued prompt admitted at `turn_done` could slip its user line **between** the previous turn's `tool_use` and `tool_result` lines — harmless in memory that day (the map held the true order), but after the next restart every turn re-sent the split pair → Anthropic 400 → the session permanently wedged, turns dying **before the model ran** (apex1 session 35: André's "you here fren" interleaved into APEX-1's a2a delta; apex2's letter three days later was the first message to hit the reloaded thread and it just… never got seen). Fixes: all three appends are **inline-awaited** (the turn's delta persists before the slot guard drops = before the next prompt can append; `TurnComplete` already went out in `run_turn`, so nothing user-visible waits), `run_turn` commits an honest `⊘ (empty reply)` marker instead of `content: []` (a second reload landmine found in the same file), and `SessionStore::load_all` runs the pure, unit-tested `apexos_core::history::repair_history` on every session — drop empties, restore `tool_use`→`tool_result` adjacency (displaced messages move after the pair; a result missing from the file entirely synthesizes an honest `LOST_RESULT_MARKER`), strip stray results, user-first. Repair is **deliberately minimal** (only shapes the API rejects — benign `user,user` from an errored turn is field-accepted and left alone), **byte-identical on clean histories**, and heals in memory only (the on-disk file stays as-written — append-only doctrine). Forensics on a suspect file: `APEXOS_REPAIR_CHECK_FILE=<file> cargo test -p apexos-core repair_check_file -- --nocapture`. **Don't reintroduce a detached session-store append, and don't "improve" repair into a beautifier — it must never mutate a history the API would accept.**
- **`/ws` inbound is `ClientEvent`, never the full `Event` enum.** The browser socket used to `from_value::<Event>`, so a tokened client could emit `ToolRequested` / `ToolResult` / `SpawnAgent` / `AgentMessage` / sensor / plugin frames whose `session`/`parent` the gateway did not replace. `ClientEvent` is the only type `/ws` deserializes: `user_prompt`, `user_approval`, `user_cancel`, `hello`, `set_persona`. Prompt/approval/cancel are translated to `Event` **after** the gateway stamps the socket session (a client-supplied `session` is ignored). Hello/persona stay control-plane and are not bus events. `/sensor-bridge` has its own `SensorIngress`. **Don't go back to `from_str::<Event>` on a client socket.** Session *resume* ownership (who may `hello{resume_session}` a given id) is finding 2.
- **Pending approvals are bound to session + nonce and die with the turn.** The supervisor's `pending_approvals` map is keyed by `ActionId` (a global counter — predictable) but a grant is accepted only when the inbound `UserApproval` carries the **same session** (gateway-injected from the socket, not client-supplied) **and** the random `nonce` minted on `ApprovalPending`. A mismatch leaves the entry in the map — a guessed id must not consume it. Entries are purged on `UserCancel`, `TurnComplete`, and `ToolResult` (the last covers the turn-loop timeout that synthesizes an error without going through the approval path). Disconnect does **not** purge: two sockets can share a session (kiosk + PWA). Old clients that omit `nonce` deserialize as 0 and are rejected. **Don't look up pending grants by ActionId alone, and don't leave a live grant after cancel/timeout.**
- **Commands ride an mpsc, not the lossy broadcast (SA-6).** `Bus::run` still broadcasts every event for the UI / event-log / health. `UserPrompt`, `ToolRequested`, `UserApproval`, `UserCancel`, `ToolResult`, `SpawnAgent`, `AgentMessage`, and `TurnComplete` are also cloned onto each `subscribe_commands()` mpsc (register *before* `run`). The router and supervisor consume that lane — a lagged `broadcast::Receiver` can no longer silently drop a prompt or a tool call (the turn used to hang until timeout). A full command channel backpressures `emit` rather than dropping. Status (sensors, plugin up/down, agent text) stays broadcast-only. **Don't subscribe the supervisor or the turn router to `bcast` for those command variants, and don't `continue` on `RecvError::Lagged` for a command consumer.**
- **Turns are serialized per session — at most one `root_turn` in flight.** The router loop drives a `TurnGate` (`admit`/`complete`/`cancel`): a `UserPrompt` for a session with a turn already running is **queued FIFO**, not spawned, and runs when the slot frees. The slot frees via a `turn_done` mpsc fired by a `TurnSlotGuard` whose `Drop` runs on completion, abort **and** panic (so a cancelled/crashed turn can't wedge the session). The loop is a `tokio::select!` over the bus and `turn_done`. Without this, two concurrent prompts each spawned a turn → the second's abort handle overwrote the first (uncancellable), their history writes raced (later wins, drops messages), the disk JSONL diverged, ActionIds collided. **All** turn-spawning paths funnel through the one `UserPrompt` arm (sensor alerts + a2a messages re-emit `UserPrompt` on the bus), so they're covered too. **Don't spawn `root_turn` outside the gate, or you reintroduce the race.** `UserCancel` clears the session's queue ("stop means stop"); sub-agent (`SpawnAgent`) turns use unique child ids and are not gated (no per-session concurrency). **Delete/archive is the same gate (SA-8):** `DELETE /api/sessions/{id}` and `POST .../archive` send a `SessionRetireReq` into the router — `TurnGate::retire` drops the queue and refuses new admits, the in-flight turn is aborted, and a **tombstone** makes `SessionStore::append` + late `histories.insert` no-ops so they cannot recreate the JSONL. **Don't delete the file from the gateway handler** (that raced the persist).

- **The Tier-4 courier lane (ApexNET P2) — sticks are untrusted media; the crypto laws are load-bearing.** `courier.rs` (apexos-plugins) turns an exo-workspace stick into an announced/ledgered/verified/receipted mesh link: `courier_queue` → `<log_dir>/outbox.jsonl` → drain-to-stick on plug (`apexos-courier/`: PSK-sealed `manifest.json` + `receipts.json`, content-addressed `cargo/<blake3-root>`) → Tier-1 gossip (`POST /api/courier/{manifest,receipt}`, `from` ∈ peer registry like every mesh endpoint) → plug-verify at the destination → receipt both on-stick and gossiped home. The laws: (1) **sealed artifacts are AAD-bound to `(domain, stick_id)`** — a manifest copied to another stick or renamed to receipts.json must fail authentication; never weaken the AAD. (2) **Tamper fails closed AND loud** — mismatched cargo is refused with an `accepted:false` receipt that travels home; never ingest unverified bytes, never fail silently. (3) **`stick_id` (marker v2) is the ledger identity, the label is only the mount convention** — v1 markers upgrade in place on plug (`ensure_stick_id`), don't add a re-prep requirement. (4) **No PSK → courier crypto disabled honestly** (plain exo-workspace + a truthful notice), never a fallback to unsealed manifests. (5) **Nothing on a stick auto-executes** — cargo lands in `workspace/courier/incoming/<origin>/` as data; `origin` is a single path component (`safe_origin`) and filenames go through `safe_name`. Receipts bind `shipment_id` + dest (+ stick when loaded), never root+dest alone — a replay of an old receipt cannot close a later shipment of the same bytes (SA-4). (6) One process writes outbox/ledger/stick files — every mutating path goes through the module `lock()`; don't add a second writer (the W2 one-writing-daemon rule). - **The brainstem outbox: seal at DRAIN, not at queue (ApexNET P4d).** Store-and-forward keeps the **plaintext** packet in flash, never a sealed frame. Sealing binds a counter, and a frame that waits a day in flash surfaces with a counter far below everything sent since — which every correct receiver rejects as a replay. Seal on the way out, with a fresh counter. (Plaintext at rest costs nothing here: it shares a partition with the colony key, so anyone who can read one can read the other.) A message is **retired only on an `Ack`**, so an unheard one stays queued; the sender remembers the counter it last sent the head under and matches the ack against it. Drain only when the target is a **live neighbour** — broadcasting into the void burns counters and proves nothing. The queue **refuses new messages when full** rather than overwriting old ones (`push(.., allow_overwrite_old_data = false)`): dropping a message already promised delivery is worse than declining a new one. Known limitation, deliberate: the head blocks — one message for an absent peer holds up those behind it.
- **The `apexnet` partition is SPLIT and the boundary is load-bearing (ApexNET P4d).** `sequential-storage`'s map and queue each own their range exclusively and will corrupt each other sharing one, so the partition is `0..0x8000` map (identity, key, counter high-water) and `0x8000..0x20000` queue (outbox). **Moving either boundary invalidates existing boards** — records written under the old split can fall outside the new range, where the store simply will not find them and the board looks silently un-commissioned. On any change to the split: `espflash erase-region` and re-commission. Also: `BlockingAsync` does NOT implement `MultiwriteNorFlash` (which `queue::pop` needs) and the async traits have no blanket `&mut T` impl, so `store.rs` carries its own tiny `FlashRef` adapter — that is why, don't "simplify" it back.
- **The brainstem outbox: seal at DRAIN, not at queue (ApexNET P4d).** Store-and-forward keeps the **plaintext** packet in flash, never a sealed frame. Sealing binds a counter, and a frame that waits a day in flash surfaces with a counter far below everything sent since — which every correct receiver rejects as a replay. Seal on the way out, with a fresh counter. (Plaintext at rest costs nothing here: it shares a partition with the colony key, so anyone who can read one can read the other.) A message is **retired only on an `Ack`**, so an unheard one stays queued; the sender remembers the counter it last sent the head under and matches the ack against it. Drain only when the target is a **live neighbour** — broadcasting into the void burns counters and proves nothing. - **Replay windows do not forget, and that is the point (ApexNET P4c).** Every receiver keeps a per-sender [`ReplayWindow`]; a counter that goes *backwards* is rejected forever, because a peer that restarted its counter and a replay attacker are the same bytes on the air. Normal operation never regresses — counters are flash-persisted with a reserved high-water (P4b). The one thing that does regress is an **`erase-region` factory reset**, and after one the *receiver* must restart before it will accept its re-commissioned peer again. Don't "fix" this by ageing entries out of the neighbour table: a window that forgets is a window an attacker can wait out. Authenticate BEFORE the replay check, too — an unauthenticated frame must never be able to advance a peer's window. **Replay state is not the 8-slot liveness cache (finding 12):** `ReplayTable` is 16 never-evict slots persisted next to the counter high-water; a full table refuses the *new* sender. A torn load fails closed (accept nothing) rather than coming up empty.
- **`apexos-mesh-bridge` (ApexNET P3) — the link laws are the v1 bug ledger; don't relearn them.** The UART bridge's `run_link` is generic over `AsyncRead+AsyncWrite` (the fault harness drives it over duplexes and real PTY pairs — `SerialStream::pair()`, no socat needed) and encodes four laws, each from a v1 failure: (1) **`read() == Ok(0)` is a LINK-DOWN event, never "no data"** — return `LinkExit::Eof`, let the FSM reconnect (backoff 250 ms→5 s, reset after a ≥5 s/frame-moving link); (2) **a fresh `Deframer` per link** — a reconnect must never inherit a half-parsed buffer; (3) **drain every complete frame per wakeup** (the deframer does this; don't add a one-frame-per-read path in front of it); (4) **the bridge is PSK-FREE** — `ct` stays opaque, the crypto envelope opens at the P5 router, so a compromised bridge process never holds the colony key; don't "conveniently" decrypt in the bridge. Deframer stats fold into `LinkStats` as DELTAS (fresh-per-link counters + process-lifetime totals — storing raw totals would reset counters on every reconnect). Not deployed by install.sh until P4 (no brainstem exists); the bench is `apexos-brainstem-sim` + a PTY pair.
- **`apexos-mesh-proto` (the ApexNET radio wire crate) is positional and frozen — postcard has no field names to save you.** Same dual-gate law as `apexos-protocol` (`cargo test -p apexos-mesh-proto` AND `--no-default-features --features alloc`), plus three laws of its own. (1) **The framing recipe is frozen**: postcard → CRC32-LE trailer → COBS → `0x00` (explicit layering — plain postcard + the `cobs` crate + `crc32fast`, deliberately NOT postcard's `use-crc`/COBS flavors); changing any layer is a `WIRE_VERSION` bump, never a silent swap. (2) **Wire types are append-only**: postcard is positional — enum variants append at the end, struct fields never reorder, nothing is removed; `tests/wire_size.rs` also locks the charter's byte budgets (Digest ≤96 B, CourierManifest ~56 B, CourierReceipt ≤44 B) against radio MTUs, so a "harmless" field addition that trips a size test means the charter numbers change in the same PR. (3) **Counters mint from 1, monotonic, persisted by every sender** — `(sender, ctr)` is the nonce; reuse is a hard-fail bug class, and `ctr == 0` is rejected at both seal and open (it's the replay window's "nothing seen" floor). The deframer is the fuzz surface: its bounded-buffer/poison-advance/resync guarantees are tested in `tests/redteam.rs` and hammered by `fuzz/` (`cargo +nightly fuzz run deframer`, 24 h clean = P1 DoD). Don't touch framing or type order without a version bump, don't hand out counters from RAM-only state, and don't "fix" a size-test failure by loosening the bound.

- **W2 mesh workers — the peer owns everything stateful; the conductor owns batch bookkeeping ONLY.** `task_fanout{node}` (per-task or batch-level) hosts plain tasks on a peer's OWN worker tier: the peer mints ordinary local workers (its cap/FIFO admission, its policy — approvals land on ITS board, its review procedure, its evidence dir + Cerebro episodes; batch parent = the conductor-peer's a2a landing session, task text carries a `[mesh: <from> batch N]` provenance prefix). Remote rows spend the SAME `next_worker_id` counter (batch rows + evidence mirrors stay uniform: the mirror lands at `agents/<local_wid>.json`, reading it IS integration; artifacts stay on the peer — `mesh_file_send` is the hand that brings one home). Their events ride `WorkerStateChanged{session: SessionId(0), node: Some(..)}` — the sentinel, because no local session exists — and the router's Parked-eviction handler **gates on `is_worker_session(session)`**: without that guard a remote "parked" mirror would evict root 0's history from RAM. Wire worker states are STRINGS, parsed tolerantly: an unknown state from a newer peer reads NON-terminal (typed rows fall back `Queued` while `timed_out` carries truth) — rolling colony updates must never break supervision. Trust: **yolo never crosses the wire** (it is not a field; the peer's policy is sovereign) while model pins DO cross (identity, not trust — the W1d distinction); all four `/api/worker/*` endpoints validate `from` ∈ the peer registry (the mesh/memory pattern, never token-only); `x-mesh-hops` refused ≥3 and depth stays ≤1 structurally (node+mandala refused — cross-node rings are M2 — so vouchers can't go remote; peer-minted remote workers are plain depth-1). Cancel relays (`POST /api/worker/cancel`, origin-conductor-only) leave rows `cancel requested` (non-terminal) until the peer confirms by poll/report — the deadline bounds a silent peer. `AGENTD_MESH_WORKERS=0` kills both directions; `/api/capabilities` gains `worker:{cap,slots_used,queued}` (the routing signal). **Don't put remote rows in workers.json, don't emit a remote mirror with a real session id, don't widen the eviction handler past the worker range, don't arm yolo from wire input, don't hard-parse `WorkerState` off the wire, don't fail a row on a poll error, and don't let any endpoint skip the `from`-registry check.** **Fanout persist-before-ack (SA-9):** `persist_worker_txn` writes one versioned `worker_txn.json` (seq + workers + batches) **before** the conductor ToolResult or the mesh `/api/worker/fanout` accept; a write failure rolls the mint back and refuses.
